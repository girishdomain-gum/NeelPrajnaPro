## What went well
1. **The harness drills itself.** It is fed a checker that cannot fail and must
   reject it — and it asserts the failed drill is not even RECORDED. That
   assertion is what stops a fraudulent drill from laundering every later claim.
2. **Drills plant violations in the REAL scanned roots**, not a stand-in
   directory. The Developer's reasoning was right: a drill against a fake tree
   proves the parser works, not that the wall works.
3. **The Developer asked instead of guessing** about leftover files it could not
   safely judge. Correct behaviour — and it surfaced F-01.
4. **Reports matched the disk exactly**, at both D-001 and D-002. Every claim the
   Architect checked was true. That is worth more than the code.

## What went wrong
- **F-01 (Architect defect).** `main` was emptied and A-001 issued without ever
  telling the Developer to clean its WORKTREE. "Start from an empty slate" was
  true of one tree and false of the other. Caught by the OWNER in his file
  explorer, not by either agent.
- **Three review fixes were needed** (R1 tamper file could survive a crash into

  describing the dead era). All small, all real, all fixed the same turn.

## Rules this sprint forged
1. **A fresh-start order must name EVERY tree it applies to.** Emptying main is
   not emptying the project: a worktree is a second working copy with its own
   disk.
2. **COROLLARY, proven here:** removing untracked leftovers produces NO DIFF —
   only two tracked files changed — so `git status` could never have revealed
   the problem. Only a real disk listing could. Second time in one week this
   class of mistake cost a turn; it is now house reflex.
3. **A limitation travels with the claim, and gets a TEST.** The dynamic-import
   hole is proven by `test_dynamic_imports_are_not_caught`, not merely mentioned.
4. **Keep the WHY beside the rule.** The .gitignore tamper entry carries its
   reasoning so a future window cannot "tidy" it away.
