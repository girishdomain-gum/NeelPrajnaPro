## J-013 · 2026-07-29 · Touch T-013 — content committed (f002b0b, pushed); script RESULT false-negative — finding F-20 (Architect)
The archive moves and README rewrite landed correctly: commit f002b0b confirmed in git log, `git push` returned "Everything up-to-date" (proof the remote already had it). The script nonetheless printed RESULT: FAILED. **Cause:** the transcript log file is being written to by Start-Transcript at the same time the script's own `git add -A` stages it, so by the time `git commit` runs, the log has grown past what was staged and git sees it as "modified" again — the script's own logging chases its own tail. Not a data-integrity problem; a self-referential logging defect. **F-20 standing rule:** ops scripts that write their own transcript into the tree must `git add` and commit in a step AFTER `Stop-Transcript`, never before — or exclude the live log path from the pre-close commit and let the NEXT script's run sweep it (the pattern already used successfully in T-007/T-008/T-012).
