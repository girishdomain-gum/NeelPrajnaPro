## What was built
Three instruments — fair value gap, order block (origin-candle method), market
structure shift — each written to a prose definition approved before any code
existed. 99 tracked files; 128 tests (was 106).

## The sprint's central experiment: the definition gate
S04's detector had something these three could not have: an external document
(Appendix B) written before the code by someone else. Without that, a detector
silently becomes whatever its implementation does. So S06 required the
Developer to write each definition as prose, send it, and **stop** — no
detector code until the Architect approved.

It worked, and the commit order proves it: definitions landed in separate,
earlier commits than the code, twice (at the gate, and again for the fix).

## What went well
1. **The definitions were better than the briefing that requested them.** Each
   carried a "mechanic a careless reader would get wrong" section — the
   nearest-versus-furthest origin candle trap in particular is exactly the
   class of thing Appendix B had to be written *after the fact* to fix in the
   previous era. Here it was written before the code.
2. **Genuine uncertainty was surfaced, not buried.** The Developer flagged
   `MAX_LOOKBACK=50` as a constant it could not defend over 30 or 100 and
   asked for a ruling rather than letting it hide.
3. **A subtle state-machine insight**: a naive stateless recomputation would
   re-derive the same trend immediately after a structure reset, silently
   defeating the rule — found by thinking about what the rule was *for*.
4. **The SDK held for three new detectors with no modification.** AM-01 said
   an interface designed from one example is usually wrong and named S07's CCC
   detector as its real test; three arrived first and it survived.
5. **Raw counts, reported without interpretation, exposed the sprint's real
   defect.** See below.

## What went wrong
- **F-05 (Architect defect).** A-018 briefed the definitions against "the
  Owner's material" — two PDFs uploaded into the Architect's chat window,
  invisible to the Developer, and the briefing never said so. The Developer
  went looking, found the Owner's own glossary at a path the Architect did not
  know existed, expanded it, and disclosed the whole chain — including a
  previous-era MQL5 file it deliberately did **not** open.
- **F-06 (shared defect).** The order block detector emitted 1,624 blocks in
  5,000 bars — one every three bars, against 153 structure shifts. A confirmed
  swing was never *consumed* by being broken, so in any sustained trend every
  bar after the first was also a "break". A **definition gap**, not merely a
  coding slip: the document said "each structure break produces at most one
  order block" but never said what makes a break *one* break. **The Architect
  approved that definition at the gate and missed it too.**

## Rules this sprint forged
1. **A briefing must never cite a source the recipient cannot open.** If the
   Architect holds material the Developer cannot see, he puts it on disk or
   quotes the relevant passages in the message.
2. **A rule that counts events must say what makes one event ONE event.**
   "At most one X per Y" is vacuous until Y is individuated.
3. **A level once taken is SPENT** — the fix reused an existing law (S02's
   burn-on-use, the sweep detector's resolved pools) rather than inventing a
   cooldown or minimum-gap parameter. Consistency with an existing rule beats
   a new dial.
4. **Raw counts carry information that prose about them would hide.** The
   Developer was forbidden from interpreting them and did not; three bare
   numbers side by side made the anomaly visible in seconds.
5. **Consume the state whether or not it produced output.** The fix clears the
   swing even when no origin candle was found — clearing only on success would
   have left the same defect alive in a narrower form, with no count looking
   wrong.

## Carried forward
- **355 is a count, not a validation.** It is the number of formations under
  one definition on one dataset. The first number looked plausible too, until
  it sat beside 153. What earns this one credibility is the mechanism behind
  the change, not the size of the number.
- All three detectors report **formation only** — no fill, re-test, or
  subsequent-break tracking. Matches what LS-01 §1.3's M5/M6/M7 rows ask for.
- "The range" order-block method remains an unbuilt, explicitly **different**
  detector, never a configuration of this one.
- MSS deliberately omits higher-timeframe bias, the CHoCH/BOS distinction, and
  any displacement requirement — each named in its own definition document. A
  stricter version is a different detector.
- `SWING_K = 3` is declared independently in two detectors, on purpose, so
  they can diverge without either being edited. Noted in both, against a
  future "tidying" pass.

## For the briefing style (S07)
The definition gate should become standard wherever no external specification
exists. And S07 is the first sprint that spends something permanent — a
registration slot and a window of market time that can never be virgin again.
It needs a slower briefing, more stop-and-ask points, and the Owner's own
ceremony inside it.
