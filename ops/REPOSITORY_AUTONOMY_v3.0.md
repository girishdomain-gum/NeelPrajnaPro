*Completes the ARO architecture. Governance, ARO and roles are **not** redesigned here — this layer only makes what already exists discoverable, verifiable and recoverable by a session that knows nothing. ## 0. The one principle that keeps this layer from becoming a liability

**Self-description is by REFERENCE and GENERATION, never by RESTATEMENT.**

A manifest that *restates* a rule creates a second source of truth for that rule, and second sources drift — F-24 was exactly that failure, caught only because a human asked. Constitution §5.1 forbids a parallel roles table; QRF-ADR-001 requires exactly one artifact per question; QRF-ADR-007 already ruled the pattern: *generated state, only two hand-maintained sections, because a stale dashboard is confidently wrong.*

Therefore, in this layer:
- every manifest either **points at** the normative source or is **generated from** it;
- every generated manifest carries the **hash of what it was generated from**;
- **a manifest whose recorded hash does not match the live source halts the boot** — it never gets used as a fallback;
- no manifest may contain a `shall`, `must` or `never` of its own. If it does, that is a finding.

## 1. Repository Boot Specification

```
 0. INVOKE      the runner starts a session with two facts it cannot infer:
                --role <role_id>   --session-identity "<model, interface>"
                (a session that is given no role EXITS; it never self-assigns —
                 self-assignment would let any session choose any authority)
 1. CLONE/PULL  git clone || (git fetch && git merge --ff-only origin/main)
 2. HALT CHECK  if ops/aro/PAUSE exists → log, exit 0. No exceptions, no override.
 3. MANIFEST    read /MANIFEST.json; verify schema_version is supported
 4. INTEGRITY   for each entry in manifest.normative[]: sha256(file) == recorded
                → any mismatch: write ops/aro/log/integrity.jsonl, EXIT NONZERO.
                  A drifted repository is not worked in; it is reported.
 5. ORIENT      read ORGANIZATION.md (what this is, the three entity categories,
                where authority lives) — pointers only, ~1 page
 6. ROLE        read manifest.roles[<role_id>]: mandate_ref (normative section),
                queue_path, write_scope, forbidden, boot_card
 7. MANDATE     read the mandate_ref itself — docs\roles\ §2.x — the real rules
 8. SPRINT      read SPRINT.json (generated): sprint id, state, gates, blocking
                decisions, acceptance criteria, frozen documents
 9. MAILBOX     list <queue_path>/inbox/ sorted by priority then age
10. CLAIM       take the top WO whose separation-of-duties check passes:
                write ops/aro/leases/WO-NNN.lease, commit, PUSH.
                push rejected → someone claimed it → pull, next item.
                nothing claimable → write a "no work" log line, EXIT 0.
11. CONTEXT     read the WO's content_ref + inputs[] + the predecessor HANDOVER.md
                (this is the entire briefing; if it is insufficient, that is a
                 defect in the predecessor's handover — raise it, do not guess)
12. EXECUTE     work; commit early and often on the WO branch; heartbeat the lease
13. PUBLISH     write ops/aro/handovers/WO-NNN/HANDOVER.md + session log;
                move the WO to completed/; release lease; commit; push
14. EXIT        clean exit. The next role's WO is created by the ARO from the
                completion event — this session tells nobody anything.
```

**Steps 0 and 10 carry the safety of the whole design.** Role comes from outside because the repository cannot know who booted; separation of duties is checked at claim because that is the only moment both facts — *who* and *what* — exist together.

## 2. Repository Manifest Specification

**Minimum set. One new root file; everything else is reached through it.**

| Artifact | Kind | Content rule |
|---|---|---|
| `/MANIFEST.json` | **generated**, machine-readable | the single entry point. Same class as `pyproject.toml`/`uv.lock` — machine metadata, which the root structure law already tolerates. Regenerated by script; never hand-edited |
| `/ORGANIZATION.md` | hand-maintained, ≤1 page | what this organization is · the three entity categories (Roles / Operational Systems / no governance bodies) · where authority lives (**pointer to Constitution §6**) · how to boot. **No rule text of its own** |
| `ops/aro/roles/<role>.boot.md` | boot card, pointer-only | queue path · write scope · lease rules · claim checks · **mandate by citation** (`docs\roles\…§2.4`). Explicitly *not* a role definition — §5.1 compliance |
| `SPRINT.json` | **generated** from Execution Plan §0/§4 + queue state | sprint id, state, gates met/unmet, blocking decisions, ACs, frozen-document list |
| `ops/ARO_Execution_Process_v2.0.md` | the workflow spec (exists) | referenced by manifest as `workflow_ref`; no `WORKFLOW.md` duplicate is created |
| *(no `OWNER_RULES.md`)* | — | **deliberately absent.** Owner authority is Constitution §6; a second copy is a governance hazard. `MANIFEST.json.owner_authority_ref` points at it |

## 3. Repository Discovery Protocol

1. **One entry point, by convention:** `/MANIFEST.json`. A session needs no other prior knowledge.
2. **Schema negotiation:** a session that does not support `schema_version` **exits with a diagnostic** rather than guessing — forward compatibility over years is bought by refusing, not by improvising.
3. **Hash-anchored discovery:** every normative path carries a sha256. Discovery therefore *verifies* as it reads.
4. **Layered depth:** `ORGANIZATION.md` (orientation) → boot card (operational) → mandate ref (authority) → WO + handover (task). A session reads only as deep as its work requires.
5. **Absence is loud:** a missing or unparsable manifest is a hard stop plus a log line, never a fallback to "read some docs and infer."

## 4. Session Recovery Protocol

| Failure | Detection | Recovery | Data at risk |
|---|---|---|---|
| **Session crash** | lease expiry (heartbeat stops) | ARO returns WO to `inbox/`, logs TIMEOUT, decrements retry budget; next session claims and reads the partial commits on the WO branch | only uncommitted work — hence *commit early and often* |
| **Token/context limit** | session self-detects near the limit | write `handovers/WO-NNN/CHECKPOINT.md` (same shape as a handover, `state: partial`, plus "next concrete action"), commit, push, release lease, exit cleanly | none |
| **Vendor/model change** | none needed | boot sequence is model-blind; the new session reads the same manifest and mandate | none |
| **Repository rollback** | manifest `generated_from_commit` ≠ `HEAD`, or hash mismatch | boot halts at step 4; a human rules whether to regenerate the manifest or restore | none — the halt is the protection |
| **Duplicate claim** | git push rejected (non-fast-forward) | loser pulls, takes the next item — the race is resolved by git's atomic ref update | none |
| **Two sessions in one role** | normal and permitted | roles are not exclusive; **WOs are**. Leases serialize the work, not the role | none |
| **ARO itself dies** | heartbeat STALE | queues remain valid (folders are the state); participants keep pulling; only *new WO creation* pauses until it returns | none |

**The recovery invariant:** *uncommitted means nonexistent.* Every protocol above is a consequence of that one rule, and it is why no recovery step ever needs a human to explain what was happening.

## 5. Repository State Model

Five state classes, in descending authority. **When two disagree, the higher wins and the disagreement is a finding.**

| # | Class | Where | Mutability | Rebuildable |
|---|---|---|---|---|
| 1 | **Ledger** (records, verdicts, burns, trials) | `datastore/` | append-only, hash-chained | no — it *is* the root of trust |
| 2 | **Normative documents** | `docs/` | versioned; frozen ones only by amendment | no |
| 3 | **Code & configs** | `qrf/`, `ivf/`, `configs/`, `tests/` | by ARCH instruction | no |
| 4 | **Operational state** (queues, leases, handovers, logs) | `ops/aro/` | append-only logs; folder moves | partly |
| 5 | **Generated indexes** (`MANIFEST.json`, `SPRINT.json`, state caches) | root, `ops/aro/state/` | regenerated | **yes, always** |

Class 5 is never cited as evidence. Class 4 has zero epistemic standing. Chat is not a class — Roles §3.6: *if chat and repo disagree, the repo wins.*

## 6. Repository Lifecycle

```
OBJECTIVE ─▶ SPRINT OPEN ─▶ WOs flow through role queues ─▶ verdict/artifact
     ▲                                                            │
     │                                        Owner ruling ◀──────┤
     │                                              │             │
     └──── handover rewritten ◀── retro ◀── sprint closed ◀───────┘

Manifest regeneration triggers (any one):
  • a normative document changes version or hash
  • a sprint opens or closes
  • a role is added, retired, or its write scope changes
  • the workflow spec version changes
Regeneration is a WO like any other; drift between manifest and source is a finding.
```

Document lifecycle is unchanged: one thing per folder, versions inside, superseded versions archived (NP-D-009). Frozen documents are listed in `SPRINT.json.frozen[]` so a booting session knows what it must not touch *before* it can touch anything.

## 7. Multi-session Coordination Rules

1. **Roles are non-exclusive; work orders are exclusive.** Any number of Architect or Developer sessions may run; each WO has exactly one live lease.
2. **One WO, one branch, one session.** Branch name derives from the WO id — parallel work never shares a branch.
3. **Separation of duties beats availability.** A session that fails the claim check returns the WO and takes the next one; an idle session is cheaper than a compromised verification.
4. **Mainline is authoritative for decision records.** Add/add conflicts resolve in favour of `main` — the precedent set 2026-07-30 when the branch and mainline both carried `ops\DEVQ-01_NP-S1.md`.
5. **Parallel workstreams are namespaced** (`WO-<track>-<seq>`, e.g. `WO-NPS2-007`, `WO-ARO-003`) and each track carries its own dependency graph; cross-track dependencies are explicit `depends_on` entries, never assumptions.
6. **No session may address another session.** Communication is WO → handover → WO. There is no messaging surface, so there is no place for an instruction to hide.
7. **Every artifact states role + session identity** (the attribution standard). Two sessions in one role are distinguishable in the record, forever.

## 8. Repository Self-Description Standard

**S1** Every manifest is generated or pointer-only; none contains an original rule.
**S2** Every generated manifest records the commit and the source hashes it was generated from.
**S3** A hash mismatch halts the boot; it never degrades to a warning.
**S4** Exactly one entry point (`/MANIFEST.json`); adding a second is a finding.
**S5** No manifest, boot card, or queue artifact names a model as a role holder (organization ADR).
**S6** A session that cannot determine its role, validate the manifest, or find its mandate **exits without working** and writes why.
**S7** Manifests describe *what exists*; they never describe intent, plans, or aspirations — those live in the Execution Plan.
**S8** The standard applies to itself: this document is DRAFT until ratified, and `MANIFEST.json` will cite the ratified version, not this one.
