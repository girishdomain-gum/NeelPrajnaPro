## What was built
A record store where any edit, deletion, reordering or half-written record is
detectable, and a window ledger where market time is spent once and can never
be spent again. 10 new files in 4 folders; 37 tests (was 14); 14 drills.

## What went well
1. **Atomicity by construction.** The briefing asked for an argument that a
   crash cannot leave a window "consumed but unburned". The Developer removed
   the need for the argument: consuming IS burning, one append, one event. The
   bad state cannot be named, so it cannot be reached.
2. **D9 vs D10 split.** "Burned once per hypothesis" would have passed a naive
   test while being strictly weaker than "burned forever, for any hypothesis".
   Seeing that distinction is the difference between honest and tidy.
3. **One mechanism, not two.** The ledger is built ON the record store, so
   every window guarantee is transitively a store guarantee. One thing to keep
   sound.
4. **`balances()` recomputes rather than caching.** A cached counter is a
   second place truth can live and drift.
5. **Parquet declined with a reason** — no real data yet to validate a format
   choice against. A format chosen against nothing is a guess wearing a
   library's name.
6. **The Developer's R1 answer beat the Architect's suggestion** (see below).

## What went wrong
- **F-02.** The atomicity drill (D14) PASSED while the failure it exists to
  catch was still live. A real crash leaves both a torn tail and a stale writer
  lock; the recovery function itself needs that lock, so a genuine crash left
  the store unrecoverable without hand-deleting a file — documented nowhere.
  The drill had simulated the crash by writing incomplete bytes, never by dying
  while holding the lock. Found by the Architect READING the code, not from the
  report.
- **R2:** recovery rewrote every line of the file while its own comment claimed
  it did not.
- **R3:** the ledger's real boundary was implicit rather than stated and tested.

## Rules this sprint forged
1. **A drill must reproduce the REAL failure mode, not a convenient stand-in.**
   A check shown to fail only in a way that cannot happen has not been shown to
   fail.
2. **When writing a limitation, ask what happens when the HOLDER of the
   mechanism dies** — not only when a second party contends for it.
3. **Recovery removes bytes; it never re-emits them.** Proven by a
   byte-identical assertion, not an equivalence one — an equivalence test would
   have passed against the broken code.
4. **A safety mechanism must never lie about being safe to bypass.** Automatic
   stale-lock detection was REJECTED by the Developer and the Architect
   accepted the correction: PIDs are reused, liveness checks differ by
   platform, and a timeout can break a lock a merely-slow writer still holds. A
   false "safe to proceed" is unrecoverable; a block is only inconvenient. The
   human states "the writer is dead, not slow" — judgment sits where the
   knowledge is.

## Carried forward
- **The ledger can only police time it knows about.** An unreserved-but-seen
  span can still be designated VIRGIN. No program can watch a human read a
  chart. This is the seam the S05 Owner ceremony exists to close — the typed
  designation is the human key on a lock the machine cannot turn alone. Named
  in ledger.py and proven by `test_r3_unrecorded_look_is_not_detected`.
- Crash recovery is deliberately MANUAL (`break_lock()` then
  `recover_torn_tail()`). Operators must know this; it is in the docstring.
- The filesystem lock is single-machine only. Not a claim this system makes.
- Bulk-store on-disk format is still open; S03 chooses it against real data.

## For the briefing style (S03 onward)
Specifying PROPERTIES and REFUSALS rather than implementations continues to
work — the best decisions in S02 were ones the Architect did not specify. Keep
demanding the reasoning, not just the result: R1's correction arrived because
the Developer was expected to argue, not comply.
