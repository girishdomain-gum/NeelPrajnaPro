## What was built
Real market data now enters the system with its integrity provable. 5,000
XAUUSD M5 bars exported from the Owner's own terminal, hash-bound, ingested
through S02's store. Exact-symbol enforcement, provenance twins, a verifier,
ingest that cannot skip verification, and a self-policing clock probe.
57 tests (was 37). CI moved to windows-latest.

## The incident (F-03) — the sprint's defining event
A bare `mt5.initialize()` silently connected to a **different broker's LIVE
account** (Winprofx-Live, 183992, real-money mode) instead of the pinned
Vantage demo, because that API attaches to whatever terminal happens to be
running. Only read-only calls were made; no order was placed.

What made this end well rather than badly:
- The Developer **stopped all further calls** the moment it noticed, rather
  than finishing the export.
- It **deleted** the files that run produced instead of keeping them as
  "probably fine" data.
- It **asked** before touching anything again.
- It reported the whole thing, unsmoothed, at the TOP of its sprint report.

The fix was structural, not a guard: the terminal is now launched by its
exact executable path via MT5's own `/config` `[StartUp]` mechanism, so
"whichever terminal is running" no longer exists in the design. The
`MetaTrader5` package was dropped entirely. `TerminalMismatch` remains as
defence in depth — because "the design should prevent it" is not the same
claim as "and here is a check that would have caught it anyway". The
incident's real values are now a permanent test.

## What went well
1. **The Owner's screenshot corrected a pin before code assumed it.** The
   previous era's `--point 0.001` describes `XAUUSD.crp`, not `XAUUSD`. The
   real export confirmed digits=2, point=0.01. Inheriting the old value would
   have made every price-distance measurement wrong by ten times, silently.
2. **The Developer caught itself** backing a clock offset out of a recalled
   timezone and stopped — applying the briefing's own prohibition to its own
   work in progress, unprompted.
3. **Checking PyPI for a Linux wheel** before adding a dependency, rather
   than discovering it in a red CI run.
4. **E4's signature-inspection test** proves no skip-verification parameter
   EXISTS — that the bypass cannot be written, not merely that it wasn't.
5. **Asked before touching S01 plumbing** (the CI platform) rather than
   changing it unilaterally.

## What went wrong
- **F-04.** The measured clock value varied by ~49s across three runs — it is
  `true_offset + round_trip_latency`, not a timezone constant, but it was
  NAMED like one and sat in the provenance twin looking like one. The first
  S04 code converting bar times would have been wrong by up to ~90s, silently
  misassigning events near M5 bar boundaries. Found by the Architect noticing
  the three numbers disagreed.
- The original briefing (A-007 §3.1) assumed the live IPC API without
  considering what it actually attaches to. That was an Architect assumption
  the Developer had to discover the hard way.

## Rules this sprint forged
1. **A live-attach API must never be trusted to connect to "the right one".**
   Launch the specific install by explicit path; leave nothing ambient to
   attach to by accident.
2. **A measured quantity must be NAMED for what it is, never for what it
   approximates.** If latency, noise or an upper bound is baked into a number,
   the name and the record must say so — or the next sprint inherits it as a
   constant.
3. **The observation is immutable; the description may be migrated.** Metadata
   around a recorded observation may change only when the binding hash is
   untouched, the change is disclosed, and the record is re-verified against
   the real file. If the hash must change, the answer is a NEW export.
4. **CI must run on the platform the code actually runs on.** A green light
   from a platform we never deploy to is a weak assurance that looks strong.
